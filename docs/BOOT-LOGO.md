# Use your own X10 boot logo

This optional workflow changes the **still image shown before Android's boot
animation**. It does not replace the Android animation or change the factory
hardware configuration. It is separate from disable-only debloating:
**installation writes the splash partition and the OEM updater restarts Android.**

The source owner's logo was installed through this OEM path on 29 October 2026.
The complete resulting partition matched an independently predicted checksum;
the owner confirmed correct appearance and normal home-screen/audio return.
The portable workflow has simulated transport tests. Its raw restoration helper
has not been physically trialed. Another unit still needs its own backup and
feature checks. No personal logo, OEM APK, firmware image or device backup is
included in this repository.

## Compatibility and access

Use the [stock profile](../profiles/stock-20260403.json) and the narrower
[logo profile](../profiles/boot-logo-20260403.json). This release supports the
reviewed X10G2A7E application `20260403.140715`, Android 13/trinket and panel
configuration 4 with the reviewed rotation policy. The script checks firmware,
three hardware APKs, the updater and the existing stock `su` executable. A model
name alone is insufficient. Other panels, firmware and S8 models need review;
do not edit hashes or add an override to bypass a mismatch.

The backup and restore commands use the **already installed stock**
`su 0,2000` direct-command route. No root manager, root daemon, helper APK,
property toggle or authentication change is installed. An intermediate shell
after `su` loses the useful credentials; the tool directly executes the reader
or writer instead. Normal debloat in `x10.py` does not use this route.

Use Python 3.11+, Android Platform Tools and the owner's trusted Wi-Fi ADB
connection. Use an explicit connection serial throughout. Reconnect to a new
wireless port after reboot if necessary; retain the same physical unit and
backup. `--adb PATH` and `--serial SERIAL` precede the command.

## 1. Prepare and review the image on the PC

Install the optional image dependency in your normal local Python environment:

```powershell
python -m pip install -r requirements-logo.txt
python tools/boot_logo.py prepare --image MY_LOGO.png --out .local/my-logo
```

PNG, JPEG, BMP and still WebP are accepted. Animated images are rejected. The
tool respects EXIF orientation, fits without cropping or stretching, places the
image on black, flattens transparency and writes an uncompressed 24-bit BMP.
The default canvas is 1280 x 720, matching the support limit. For a smaller
canvas use, for example, `--size 880x572`. No dimension may exceed 1280 x 720.
The input is limited to 16 million pixels and 32 MiB. Do not pre-rotate the logo;
the OEM updater handles panel rotation. Open `.local/my-logo/preview.png` for
owner review before installation. Preparation makes no device connection.

Outputs include the preview, hashed `kit.json`, `logo-usb.zip` and:

```text
usb-root/
  Upgrade/
    qcm6125_T10.txt
    zh_logo.bmp
```

The marker is generated by this tool; no vendor download is required. The
[support package supplied by the owner](https://atoto-usa.oss-us-west-1.aliyuncs.com/2025/library/15193536/Upgrade.zip)
was inspected: it is 335 bytes and contains only an `Upgrade` directory and the
X10 model marker, with no image or firmware. Its SHA256 is
`1403618d59ae1642d46eb404e2d2cf12641ea87beb1f5d82e37b18d6b2e030f0`.
The [supplied reference video](https://atoto-usa.oss-us-west-1.aliyuncs.com/2025/library/15380211/Upgrade.mp4)
was not viewed for this workflow.

## 2. Back up this unit before any logo update

First follow the [agent runbook](AGENT-RUNBOOK.md) for the private APK/settings
snapshot, native launcher export and before-trial feature checks. Those snapshots
do **not** back up the splash partition. Then run:

```powershell
python tools/boot_logo.py --serial SERIAL backup --out .local/splash-before
python tools/boot_logo.py verify-backup --backup .local/splash-before
```

The first command reads the entire splash partition over Wi-Fi, compressing it
on the wire. Device-before, PC and device-after checksums must agree. The result
is the full `splash.img`, compressed copy, identity-bound metadata and captured
HOME/core/package state. A partial transfer never becomes a verified backup.
If interrupted, preserve the incomplete folder and choose a new capture folder.
`verify-backup` is offline. Copy this verified backup to another storage device.

Use each owner's original image and backup. The updater's
`back_update_folder/logo.img` is the **new generated logo**, not a backup of the
previous splash. A downloaded ROM or APK/settings snapshot is not a substitute.

## 3. Stage, then authorize installation and restart

No other update should be running. Keep the vehicle parked and its power stable
through the update. Determine whether the owner is ready for the screen,
audio and camera interruption; earlier permissions from another session or
another owner do not establish that readiness.

```powershell
python tools/boot_logo.py --serial SERIAL stage --backup .local/splash-before --kit .local/my-logo
python tools/boot_logo.py --serial SERIAL stage --backup .local/splash-before --kit .local/my-logo --execute
python tools/boot_logo.py --serial SERIAL install --backup .local/splash-before
```

The first command previews. Executed staging transfers only the marker and BMP
into an isolated folder, verifies their hashes and journals the expected full
partition checksum. It does not open the updater or reboot. An interrupted
stage may be retried with the same backup and kit. Unrecognized files in its
update folder stop the operation; nothing is bulk-deleted.

After the owner approves the reviewed image and is currently parked/ready:

```powershell
python tools/boot_logo.py --serial SERIAL install --backup .local/splash-before --execute --parked --allow-reboot
```

This starts the existing OEM updater against only that isolated folder. It
requires the dialog to contain **Upgrade LOGO only**, selects it, then confirms
Upgrade. The automated dialog check expects that English label; another
translation stops for inspection. It does not use an OS/MCU/Bluetooth package. Intent is journaled before
the service call because the updater can retain an automatic-update preference.
The service writes a 16 KiB prefix plus its panel-rotated BMP to `splash`, then
automatically restarts Android. No other partition is a tool-selectable target.

If the connection drops or the dialog is unexpected, **do not replay install**.
The journal blocks repeated confirmation. Reconnect and run verification below.
If the original checksum remains and the updater is idle, inspect the recorded
step and dialog before deciding on a manual continuation or a fresh attempt.
Do not delete the journal to force a retry. An agent may inspect the current
logo-only dialog and complete an already-authorized confirmation only after
establishing that no update started and the owner remains ready.

## 4. Verify after the reboot

```powershell
python tools/boot_logo.py --serial CURRENT_SERIAL verify --backup .local/splash-before
```

Verification requires a different boot ID and an exact match of the **whole
splash partition** against the predicted new image, including the untouched
tail of the original. It checks firmware/hardware state, default HOME and the
previously enabled protected packages. SIM state is reported for review.
Read warnings and repeat the [physical feature matrix](FRIEND-TRIAL.md).

Ask the owner whether the logo is correctly oriented and sized, and whether
the home screen/audio returned normally. Check cameras/DVR, Bluetooth, CarPlay
and physical-SIM data separately. Save only observed results privately; the
tool's `physical_confirmation: null` is not a passing physical test. An agent
must not infer all hardware works from a checksum or enabled package list.

## Restore the original still logo

```powershell
python tools/boot_logo.py --serial SERIAL restore --backup .local/splash-before
python tools/boot_logo.py --serial SERIAL restore --backup .local/splash-before --execute --parked
```

The first command previews without writes. Execute only within the owner's
restoration authorization. The helper checks the original full backup, device,
firmware, partition mapping/size and the known new checksum, transfers the
compressed original, then writes **only splash** with the existing stock
command route. It verifies the full original checksum. Already-original is a
no-op. It does not reboot; an owner-controlled restart is needed to view it.
This restoration path is host-tested but not physically trialed on the source
unit. A verified backup alone does not prove recovery from an unbootable unit.

An unknown/partial splash, changed firmware/panel, missing staging directory or
failed restore checksum stops automation. Preserve the backup, journal and
error. An experienced agent must inspect a fresh full read, verify the exact
saved source and target mapping, and obtain the owner's recovery authorization
before a narrowly scoped manual restoration. Do not switch slots, factory reset,
flash an OS/MCU image or weaken firmware/identity guards to recover a logo.

The Android animation is separate; restoring splash does not change it.

## USB alternative

The generated USB ZIP is also suitable for the quoted support procedure on a
reviewed compatible unit, after the same complete backup and parked readiness
checks. Extract it so `Upgrade` is directly at the USB drive root, containing
only the two listed files. Connect the drive to the X10 USB cable, select only
the logo component, then Upgrade; expect the OEM restart. Do not include old
firmware, auto-update or wipe files. This release's automatic verification is
bound to its Wi-Fi staging journal; for a purely manual USB install, retain the
backup and image and separately inspect/read back the result. Do not claim the
automated `verify` covered an unjournaled USB installation.

The FactoryTools logo selector concerns preset BMPs and can share a page with
unrelated hardware setters. This workflow does not need a factory PIN, a
configuration Save/Restart, or changes to panel voltages or vehicle settings.

Generated images, ZIPs, snapshots and device journals belong in ignored `.local/`
or outside the repository. Publish source and sanitized observations only.
